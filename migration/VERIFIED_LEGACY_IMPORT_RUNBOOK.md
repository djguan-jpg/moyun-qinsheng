# Verified legacy import runbook

This runbook is inert until an authorized operator supplies an offline verified backup and explicit production confirmations. Never place its private SQL or rollback ledger in this repository.

1. Freeze writes. Export D1 with `wrangler d1 export <exact-name> --remote --output <private-path>` and make a versioned R2 inventory/backup. Record hashes and confirm the exact account, D1 ID/name, R2 bucket and deployed Worker version. Abort unless the supplied state is exactly the reviewed 14-work manifest.
2. Run the importer in `dry-run`, then `reconcile`. Both modes are read-only and must report 20 registrations, 14 reused objects and 6 new objects. Review the non-sensitive plan hash.
3. Use `prepare` only with `--production` and all four exact confirmation flags. Keep `--private-output` outside the checkout. Review the generated private SQL and rollback ledger on the restricted operator host.
4. Upload only the ledger's six new objects to their random private keys, with content type and SHA-256 metadata. Read each back and verify size/hash. Never overwrite or delete the 14 existing objects.
5. Apply migration `0005` first. With the reviewed Wrangler 4.127.1 version installed locally, execute the generated import as an argument vector (never a shell-joined string): `node_modules/.bin/wrangler d1 execute <exact-name> --remote --file <private-path>/import.sql --yes`. Never use `npx`: a download or version substitution is forbidden. The file intentionally contains no explicit transaction-control statements. In Wrangler 4.127.1, `--file` uses D1's dedicated `/import` ingestion API (`init`, upload, `ingest`, then `poll`), not the ordinary `/query` path and not `D1Database.batch()`. Wrangler states that an incomplete ingestion returns the database to its original state; this procedure additionally requires a disposable remote mid-file failure proof for the pinned version. Abort on any nonzero exit; do not retry until step 6 reconciliation proves whether the plan is already complete.
6. Reconcile 20 unique owners/public IDs/orders, 20 active owned registrations, zero active anonymous duplicates, 14 reused plus 6 new objects, no orphans, private-field absence, same-origin capabilities, Range/HEAD/ETag, and protected-route fail-closed behavior.
7. Deploy only after separate approval. Acceptance requires Worker-first headers on `/`, `/works`, `/register`, `/vote`, and `/admin`, plus the full security suite.

The live audio proof preserves the Worker's 80 requests per 60-second fixed-window limit. It verifies four objects with five semantic requests each, performs one tamper and one expiry mechanism check (22 audio requests), waits exactly once for 61 seconds (hard ceiling 65 seconds), refreshes the exact 20-item public listing and capabilities, then verifies the remaining sixteen objects with 80 requests. One additional `HEAD` to a valid audio capability must be request 81 and return `429` with an integer `Retry-After` from 1 through 60. `/vote` is a public HTML page; only authenticated registration, vote, logout, and representative admin surfaces belong to the generic protected-route fail-closed gate. Browser evidence navigates `/`, `/works`, and `/vote` separately and rejects any non-200/empty page, cross-origin or retired link, redirect, or loading failure.
8. Roll back by restoring the verified D1 export and prior Worker version. Delete only the six keys listed in the private ledger after confirming they were created by this run. Never delete the original 14 objects or the legacy backup.

## Adapter safety gate (package 2)

`tools/production_complete.py` defaults to offline validation and requires `--production` plus all four exact confirmation values before constructing the production adapter. Its private JSON config, token, audio sources, import SQL, D1 export, R2 readbacks, live evidence, and atomic mutation receipt ledger must use canonical paths outside the checkout. The config includes the exact account and zone IDs and a closed `expected_queries` map containing only `baseline:compatibility`, `post_import`, and `post_rollback`; each value is a closed `{sql, expected}` object and both fields are representation-redacted. The obsolete `live_evidence_command` field is rejected. Any existing receipt means `RECONCILE_NEEDED`; mutations are never automatically retried.

The adapter captures the active Worker version and D1 Time Travel bookmark before mutation, restores the exported SQL into an isolated SQLite database for `quick_check`, `integrity_check`, and `foreign_key_check`, downloads the exact 14 legacy keys, and verifies every object against size, SHA-256, magic bytes, and an exact Content-Type metadata proof. The locally pinned Wrangler provides the D1/R2/Worker commands. Because Wrangler 4.127.1 does not expose R2 object Content-Type or custom-domain enumeration through the relevant read-only commands, a separately reviewed read-only evidence runner must provide those official-API proofs with the adapter's closed JSON schemas.

The adapter uses separate Wrangler and evidence runners. Wrangler accepts only its private explicit method; generic command execution is forbidden. The evidence runner accepts only four fixed modes and invokes the fixed repository path `tools/live_evidence.mjs` with the locally installed Node executable, `shell=False`, and an argument array. No config-supplied command is accepted, and the token is environment-only. The helper is fixed to the canonical contest origin and the official Cloudflare API origin; fixture origins are available only through module-call injection and cannot be selected by CLI, environment, or config.

Before every mutation, source preflight verifies the import SQL hash as well as all object sources; import verifies the SQL hash again. Cloudflare preflight must freshly produce a nonce-bound closed envelope whose result contains exactly seven true ownership/resource fields: account, zone, Worker, D1, R2, canonical domain, and resource-ID match. Metadata, public-access, and live-gate evidence use their own closed schemas. A pre-existing preflight, metadata, public-access, or live evidence output is `STALE_EVIDENCE` and is never reused.

Each of the six private-plan uploads is recorded as `r2-put-0` through `r2-put-5`, with before/after `created` and `succeeded` booleans but no object key. Deletes use the corresponding `r2-delete-0` through `r2-delete-5`. Operators reconcile a crash by combining the private plan with this index; the 14 legacy entries are never deletion candidates. Rollback reconciliation runs its independent `post_rollback` QuerySpec and must prove 14 anonymous, zero owned, zero users, and zero registrations rather than treating the requested owner count as database state.

Package 4 completes the two previously unavailable modes. Exact-object evidence uses Cloudflare's fixed bearer-token Get Object endpoint, preserves literal key slashes, streams bytes under the manifest-derived bound, and independently verifies normalized Content-Type, magic bytes, actual size, declared length, and locally computed SHA-256. The live gate combines closed canonical-origin HTTP checks with an isolated Microsoft Edge CDP network/DOM inventory and emits only the exact state-machine booleans and counts. Any incomplete check fails before an evidence envelope is written.

`LIVE_ACCEPTED` remains possible only after the core succeeds, the exact token file is absent, and fresh nonce-bound live evidence passes its closed schema. This helper does not itself authorize a production run, deployment, or mutation.
