# Production gate and operations runbook

Nothing in this document is active merely because it is committed. Every item below is an external deployment gate.

1. Obtain an authoritative old-host SQLite snapshot and upload tree. Make two verified copies in separate failure domains, compare archive hashes, restore one copy, rerun SQLite integrity/counts and every file hash. Do not substitute public downloads.
2. Create isolated staging D1/R2/Worker only after authorization. Apply versioned migrations locally/reviewed first. Run `tools/plan_backup_import.py` with explicit snapshot, upload, and manifest paths in its default dry-run mode. Review count/hash/orphan reconciliation. Only a later authorized operator may add `--apply`, a staging target, and the staging guard. Import must record the source hash/counts in `migration_imports`.
3. Configure the Discord app with exact staging and production callback URIs, confidential secret, `identify guilds.members.read`, guild and role IDs. Confirm S256 PKCE at staging. Configure `CANONICAL_ORIGIN`, high-entropy capability secret, Turnstile site/secret keys, Access audience/team/JWKS, D1 and private R2 bindings without exposing values.
4. Create Access policy as boundary one. Merge—not replace—WAF/rate rules using `security/cloudflare-controls.json`; retrieve the complete current ruleset and review its diff. Keep the callback skip limited to Browser Integrity Check only. Configure Turnstile hostnames.
5. Activate Workers/D1/R2 usage alerts and budgets, structured logs containing request ID/event/outcome and hashes only, never tokens, identities/contact, filenames or R2 keys. Alarm on authorization failures, scan/budget blocks, 5xx, D1/R2 usage and an open circuit. Confirm on-call owner and circuit reopen procedure.
6. Run staging abuse/security tests: 401 vs 403, stale roles, CSRF/origin, OAuth replay/expiry, session rotation/logout/expiry, body limits, Turnstile, account/IP limits, HMAC tamper/expiry, public-ID scans, pagination cap, daily/global circuit, file validation/rollback, privacy, Range/HEAD/ETag/416, viewer denial, Access JWT and asset fallback. Perform malware/content review appropriate to accepted audio.
7. Reconcile staging rows by public/test/private class, votes and uniqueness, R2 objects/bytes/full hashes, missing/orphan objects, gallery order and anonymous JSON. The six missing old-host files and two uncertain bundled files must be resolved only from database/backup evidence.
8. Schedule cutover freeze. Take a fresh two-copy backup/watermark, import the delta into staging, reconcile, freeze old writes in the approved window, import/reconcile final delta, then promote the reviewed artifact/config. Do not copy secrets between environments casually.
9. Acceptance: same-origin home/gallery/playback, OAuth/roles, registration edit/audio replacement, active-stage idempotent vote, Access+admin/viewer behavior, exports/settings, observability, budgets and restore drill.
10. Roll back on auth/role errors, count/hash/orphan mismatch, missing audio, corrupt ranges, vote inconsistency, elevated 5xx or cost alarms. Route to the prior Worker/static version, reopen old writes if safe, preserve new D1/R2 for forensics, and never reverse-import automatically.
11. Decommission the old site only after written acceptance, rollback window expiry, final verified backup, retention assignment and successful restore test.
